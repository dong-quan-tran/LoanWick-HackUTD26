# Deterministic evaluation

Run npm run evaluate. Expected results are maintained independently in fixtures/expected-results/demo.json rather than generated by the checks being evaluated.

The evaluator validates the complete snapshot, synthetic identity records, document SHA-256 hashes, actual excerpt substrings, JSON field locators/extracted values, every case's expected concern types/sources/evidence/facts, and the planted stale payment review. It exits nonzero for mismatches or invalid source references. npm test additionally covers regression boundaries, meaningful negative controls, revision invalidation, projection privacy shapes, and policy readiness.

Current fixture set:

- Eight applications and eight JSON source documents.
- Fifty-one source evidence records, including amount/currency and hostile document text.
- Four expected case-level findings: one collateral conflict visible on two applications and one group-review concern visible on two applications.
- Two distinct underlying concerns after deduplication.
- Four negative-control/missing-input applications with no invented collateral/group verdict.
- Payment verification for app-office-a is stale: current revision 2, observed revision 1.

The local evaluation found all four expected case-level findings with zero missing/unexpected findings and zero evidence/fact mismatches. These are planted fixture outcomes, not real-world fraud precision/recall. Runtime is printed per execution; no latency target or benchmark is claimed.

No live model explanation quality, extraction of arbitrary customer documents, real server permissions, transaction races, browser flow, or banking accuracy is measured here. Hostile text is stored and tools exclude privileged operations; this does not prove that an unimplemented model worker resists prompt injection. Those tests must be run against the real worker and database.

When adding a case, add a distinct application ID, canonical source with a synthetic label, document hash/version, real evidence locations, explicit expected positive/negative outputs, and appropriate tests. Updating a source requires updating metadata, excerpts, and expectations together. Regenerate sample views deliberately with npm run fixtures:views.
